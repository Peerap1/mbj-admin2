# โครงสร้างโปรเจกต์หลัง Refactor

คง React, Firebase และรูปแบบข้อมูลเดิม โดยแยกงานตามหน้าที่ ไม่ย้ายข้อมูลจริงหรือเปลี่ยนระบบล็อกอินในรอบนี้

## ตำแหน่งโค้ด

| โฟลเดอร์                 | หน้าที่                                                               |
| ------------------------ | --------------------------------------------------------------------- |
| `src/pages`              | หน้าของแต่ละ route ประกอบ UI และประสานงานกับ hooks                    |
| `src/features/sales`     | ตะกร้า กล่องสินค้า ฟอร์มลูกค้า สรุปยอด การชำระเงิน และพิมพ์เอกสาร     |
| `src/features/payroll`   | การอ่านข้อมูลเวลาจาก workbook การจับคู่ชื่อ สูตรค่าจ้าง และส่วนแสดงผล |
| `src/features/employees` | ฟอร์มพนักงาน ตาราง และยืนยันลบ                                        |
| `src/features/reports`   | state/ตัวกรองรายงาน และสร้างไฟล์ Excel/CSV                            |
| `src/features/customers` | ตัวเลือกมาตรฐานของข้อมูลลูกค้า                                        |
| `src/components/ui`      | Modal, Button, FormField, ConfirmDialog ที่ใช้ร่วมกัน                 |
| `src/components/crud`    | ตารางและฟอร์มสำหรับหน้าจัดการข้อมูล                                   |
| `src/hooks`              | subscription ข้อมูล, การประกอบข้อมูลธุรกิจ และนำเข้า workbook         |
| `src/firebase`           | เชื่อมต่อฐานข้อมูลและ API อ่านเขียนข้อมูล                             |
| `src/utils`              | การวิเคราะห์ลูกค้าและการเตรียมค่าจากฟอร์ม                             |

## เส้นทางการทำงาน

- หน้าจออ่านข้อมูลผ่าน `useCollection(getCustomers)` เป็นต้น โดย hook ดูแล loading, error, unsubscribe และป้องกัน callback เก่ามาอัปเดตหน้าปัจจุบัน
- `useBusinessData` ประกอบข้อมูลลูกค้า สินค้า และการขายจาก hook เดียวกัน
- `database.js` ยังคงชื่อ exports เดิม ใช้ `createCollection` ลด CRUD ที่ซ้ำกัน และเก็บการสร้างรหัสลูกค้า/Order ไว้ตามเดิม
- `CrudPage` ดูแลค้นหา เปิดฟอร์ม และบันทึก ส่วนหน้าต้นทางกำหนด fields และกฎเฉพาะธุรกิจ ส่งเฉพาะค่าฟอร์มไปบันทึก ไม่ส่ง ID หรือค่าที่คำนวณไว้แสดงในตาราง
- `sales.js` เป็นแหล่งสูตรยอดขาย ค่าส่ง validation และ snapshot ของ Order; `useSaleCart` ดูแลการเพิ่ม/แก้ไข/ลบสินค้าในกล่อง
- `payroll.js` รับ workbook และข้อมูลค่าจ้าง คืนผลคำนวณโดยไม่เรียกฐานข้อมูลหรือ React; `useWorkbookUpload` ดูแลการเลือกไฟล์และการอ่าน Excel
- `SlipModal` และ `printSale` ใช้ร่วมกันทั้งหน้า Sales และ History ส่วน `slipModel` เตรียมรายการและยอดของทั้งพรีวิวและงานพิมพ์ หน้าพิมพ์ยังคงรูปแบบกะทัดรัดเดิม
- `useSalesReport` ดูแลตัวกรอง/การเลือกข้อมูลรายงาน และเรียก `exportAnalysis` เพื่อสร้างไฟล์ โดยใช้สูตรจาก `customerAnalysis.js` เดิม

## ขอบเขตที่คงไว้

สูตรเงินเดือน 9 ฟังก์ชันถูกตรวจเทียบกับก่อน refactor ว่า logic ตรงกัน รวมถึงการใช้ชีตแรกสำหรับคำนวณ การจับคู่เวลา การจับคู่ชื่อ ช่วงเวลากดแผ่น และการปัดเศษ การเปลี่ยนกฎเหล่านี้ต้องทำเป็นงานแยกพร้อมตัวอย่างผลลัพธ์ที่ต้องการ

คงฟิลด์ `dailyRate`, `pieceRate`, `isPieceWorker`, `monthlySalary`, `sales.boxes` และเส้นทาง Firebase เดิม ไม่มีการแก้ข้อมูลย้อนหลัง ฟังก์ชันสร้างเลขเอกสารยังใช้ transaction เดิม

UI หลักและรูปแบบใบพิมพ์ยังใช้ CSS เดิม มีการรวมกล่องโต้ตอบและเพิ่ม label ที่เชื่อมกับช่องกรอกเพื่อให้ใช้งานฟอร์มได้ชัดเจนขึ้น

การย้าย Firebase Authentication, เปลี่ยน database rules, ปรับสูตรธุรกิจ และ migration ข้อมูล ไม่รวมใน refactor นี้

## ตรวจสอบก่อนส่งงาน

```sh
npm run format:check
npm run lint
npm test -- --watchAll=false --runInBand
npm run build
```

ชุดทดสอบใช้ข้อมูลจำลอง ครอบคลุมการคำนวณขาย/เงินเดือน การบันทึกจากฟอร์ม การจัดประเภทพนักงาน การวิเคราะห์/Export การ escape เอกสาร และวงจร subscription โดยไม่เขียน Firebase จริง
